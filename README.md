# 臺灣交通事故資料整合分析平台

一個純前端（無需後端伺服器）的靜態網站，整合七種官方資料來源，讓使用者可以自由篩選、交叉比對、視覺化並匯出：

1. **A1 交通事故明細**（110–114 年 / 西元 2021–2025，共 8,647 件事故、22,146 筆當事者資料，逐筆載入瀏覽器）
2. **A2 受傷交通事故**（110–114 年 / 西元 2021–2025，共約 434 萬列原始資料、192.6 萬件事故 —— 因資料量遠大於 A1，網站僅載入依年度／縣市／天候／光線／道路類別／事故類型／肇因等維度**彙整後的統計數字**，不逐筆載入；逐筆原始資料可在「資料表與匯出」分頁下載 gzip 壓縮 CSV）
3. **舉發統計**（108–114 年 / 西元 2019–2025，9 大類：闖紅燈、超速 40km 以下、未戴安全帽、未繫安全帶、危險駕車、違規停車、不依規定轉彎、其他原因、總件數）
4. **縣市重要統計指標**（1998–2025，人口、人口密度、道路里程、事故傷害死亡率等 16 項長期指標）
5. **全國1000易肇事路口清單**（已完成地理編碼，含縣市、鄉鎮市區、路口名稱、原始件數/死亡/受傷、排行）
6. **永續提升人行安全計畫799處補助地點**（已完成地理編碼，交通部＋內政部兩份核定表彙整，含縣市、鄉鎮市區、路口位置/地址）
7. **各縣市道路交通違規罰鍰收入分配金額**（111–114 年 / 西元 2022–2025，政府資料開放平台 dataset 167869，22 縣市歷年罰鍰收入分配金額、四年合計與排名）
8. **科技執法設備地點**（22 縣市警察局╱交通局提供之測速照相、闖紅燈照相、區間測速等科技執法設備清單彙整，共 1,243 筆，其中 880 筆有經緯度可供地圖與環域分析；新竹縣、宜蘭縣、臺東縣、連江縣未提供資料，花蓮縣僅有 PDF 文字清單無座標，詳見下方「資料處理備註」）
9. **六都及全國交通標案分類彙整**（政府電子採購網關鍵字查詢結果，涵蓋 110/01/01～115/09/08，科技執法／標誌標線／人行道／道路工程／道路改善／拓寬工程 6 大類共 14,793 筆標案，已比對履約地點至縣市、標註與道路交通安全相關性，獨立頁面 `tenders.html` 提供互動查詢）

另外還有兩個獨立頁面（不吃側邊欄篩選，各自獨立瀏覽）：
- **`budget.html`（台灣決算地圖）**：22 縣市主計處總決算公告連結彙整、六都罰鍰收入決算比較、六都科技執法審核意見比較等。
- **`tenders.html`（六都及全國交通標案分類彙整）**：上述第 9 項標案資料的互動查詢頁面。

## 功能

- 側邊欄多維度篩選（年度、縣市、天候、光線、道路類別、事故類型、肇因），全站連動，同時套用到 A1 逐筆資料與 A2 彙整統計
- 10 大分頁：
  - **總覽**：KPI（含 A1＋A2）、歷年趨勢、縣市排行等
  - **地圖**：地圖導航（縣市／鄉鎮跳轉、座標定位＋即時環域統計、**熱點查詢**：可依縣市／鄉鎮市區〔預設為「全部」〕或關鍵字先縮小「1000易肇事路口」「799人行安全補助點位」或「科技執法設備地點（有座標者）」清單範圍；「單一點位」欄位為選填，不選則直接對目前篩選出的所有點位一次查詢（去重合計，不會因點位彼此靠近而重複計算），選了則只查該一個點位；半徑可自行輸入任意公尺數（也可從 50/100/200/300/500/1000 建議值點選），按「查詢」會在地圖上畫出對應的環域範圍圓圈並顯示 A1／A2 事故統計；「⬇ 匯出符合條件點位」則一律依目前篩選匯出「所有」符合條件的點位資料為 CSV）＋ A1 死亡逐點或熱力圖 ＋ A2 受傷熱區密度 ＋ 1000易肇事路口／799人行安全補助點位／科技執法設備位置圖層，皆可自由勾選組合顯示
  - **熱點環域分析**：選擇「1000易肇事路口」「799人行安全補助點位」或「科技執法設備地點（有座標者）」其中一份清單、選擇環域半徑（50/100/200/300/500/1000 公尺），即時列出每個點位在該半徑內的 A1／A2 事故統計，可依任一欄位排序、依縣市或關鍵字篩選，並匯出含統計結果的 CSV（選擇科技執法設備地點時，可用此表驗證「設備設置地點是否對應實際事故熱區」）
  - **多維探索**：可切換 A1 逐筆或 A2 彙整統計為資料來源，自由交叉比對
  - **事故 vs 舉發執法**：舉發類別 vs 事故件數散佈、歷年各類舉發件數趨勢、各縣市舉發件數 vs 事故件數/死亡人數，另外新增**各縣市道路交通違規罰鍰收入分配金額**（111–114年）排行長條圖，可切換單一年度或四年合計、匯出 CSV
  - **事故 vs 人口/縣市**
  - **改善趨勢分析**：整合 A1/A2 事故資料、舉發件數、罰鍰收入三份不同資料，呈現「改善比例」相關比較，共 4 張卡片：① 全國整體改善總覽（5 項安全指標各自的完整年度範圍改善%，卡片標題會標示實際使用的起始／結束年）；② 各縣市改善排行（可切換 5 項安全指標之一＋自訂起始／結束年，長條圖由改善最多排到最少，可匯出 CSV）；③ 舉發總件數變化 vs 事故／死傷改善對照象限圖；④ 各縣市罰鍰收入變化 vs 事故／死傷改善對照象限圖（罰鍰資料僅 111–114 年可選）。這兩張都是以「目前顯示縣市在 X、Y 軸的平均值」為分界線切成四象限（而非用 0 分界），每個縣市依落點象限著色，圖表下方另有清單列出各象限包含的縣市，方便快速看出哪些縣市明顯優於／低於平均、哪些縣市接近整體平均。5 項安全指標為：A1 死亡人數、A1 事故件數、A2 事故件數、A2 受傷人數、每十萬人死亡率（官方指標）。全站的縣市篩選會即時套用到此分頁（KPI 總覽卡片除外，該區塊固定顯示全國 22 縣市總計）。分頁下半段另外有「縣市道路安全結構關聯分析」，比對縣市結構性因素（道路長度、人口密度、人口年齡結構）與安全結果的橫斷面關聯，共 2 張卡片：⑤ 縣市結構因素 vs 安全結果象限圖（X 軸可選每萬人道路里程／人口密度／65歲以上人口比例／0-14歲人口比例／每萬人小客車登記數；Y 軸可選每十萬人死亡率／A1死亡人數／A2受傷人數／官方肇事總件數／A1或A2行人涉入比例，皆換算成每十萬人或每萬人標準化比率以便跨縣市比較，單一年度斷面、可匯出 CSV）；⑥ 當事者年齡結構 vs 人口年齡結構涉入比排行（比較某年齡層在事故當事者中的占比是否高於或低於其人口占比，可切換 A1／A2、年齡層、起訖年，可匯出 CSV）
  - **工程經費(標案)**：讀取「六都及全國交通標案分類彙整」資料（`data/tenders.data.js`，與獨立頁面 `tenders.html` 共用同一份資料），提供 KPI 總覽（符合篩選標案筆數／總決標金額／平均決標金額／涵蓋縣市數／涵蓋分類數）＋可自由切換的互動圖表：**圖表類型**（長條圖-總決標金額／長條圖-標案件數／圓餅圖-金額占比／折線圖-歷年金額趨勢）× **分組維度**（履約地點縣市／分類／機關所屬地區／政府層級／是否受機關補助），並可用分類勾選晶片、縣市、機關所屬地區、決標年度、相關性、是否受機關補助、機關名稱／標案名稱關鍵字等條件自由篩選，篩選結果同步反映在圖表、KPI 卡片與下方的分組彙總明細表，並可匯出目前篩選結果 CSV。此頁著重於彙總圖表與多維篩選；若需逐筆標案資料查詢與更多欄位，請至獨立的「標案彙整」頁（`tenders.html`，頁面右上角與本頁卡片皆有連結）。
  - **資料表與匯出**：完整 A1 資料表＋A2 原始資料下載
- 圖表匯出 PNG、地圖匯出 PNG、篩選後 A1 資料匯出 CSV / Excel、交叉表匯出 CSV、A2 逐年原始資料下載（gzip 壓縮 CSV）、熱點環域分析清單匯出 CSV、改善趨勢分析（縣市排行＋兩張象限圖＋結構因素象限圖＋年齡涉入比排行）匯出 CSV、工程經費(標案)分頁篩選結果匯出 CSV
- 深色 / 淺色主題切換
- 純靜態檔案，可直接部署到 GitHub Pages、Netlify、Vercel 或任何靜態主機，也可以直接雙擊 `index.html` 在本機瀏覽器開啟使用

## 如何在本機開啟

直接用瀏覽器打開 `index.html` 即可（所有資料已內嵌為 JS 檔，不需要啟動伺服器、不會有 CORS 問題）。

## 如何部署到 GitHub Pages

1. 把整個資料夾內容 push 到你的 GitHub repository（例如 repo 名稱 `traffic-dashboard`）
2. 到 repo 的 **Settings → Pages**，Source 選擇你的分支（例如 `main`）與根目錄 `/`
3. 稍待片刻，GitHub 會給你一個網址，例如 `https://<你的帳號>.github.io/traffic-dashboard/`

> 因為是純靜態檔案，之後每次更新資料只要重新 push 覆蓋 `data/*.data.js` 即可，不需要任何額外設定。

> **關於瀏覽器／靜態主機快取**：`index.html` 內對 `css/style.css`、`js/*.js`、`data/*.data.js` 的引用都加了版本查詢字串（例如 `js/app.js?v=20260908`），目的是避免使用者瀏覽器或部分靜態主機（GitHub Pages、Netlify 等）的 CDN 快取到「舊版 JS／資料檔搭配新版 index.html」而出現功能異常（例如勾選圖層後地圖無反應、新分頁沒有內容等，但實際上程式碼與資料都已經是新的，只是瀏覽器讀到了快取的舊檔案）。**之後只要更動了 `css/`、`js/` 或 `data/` 底下任何檔案內容，請把 `index.html`（以及 `tenders.html`，若有更動 `data/tenders.data.js`）裡所有 `?v=` 後面的版號一併更新（例如改成當天日期），否則使用者可能要清除瀏覽器快取或強制重新整理才會看到最新版本。**

## 如何更新 / 新增資料

這是設計給你之後持續維護用的重點：**只要把新的原始檔放進 `data_raw/`，重新執行一次建置腳本即可**，不需要改任何網站程式碼。

### 1) 新增一個年度的 A1 事故明細

把政府資料開放平台下載的 CSV（欄位格式需與現有檔案相同）放進 `data_raw/accidents/`，檔名用西元年份，例如新增 115 年資料就存成：

```
data_raw/accidents/115.csv
```

### 2) 新增一個年度的 A2 受傷事故明細

A2 資料量非常龐大（一個年度常拆成 10 幾個 CSV 檔、加總 70–80 萬列），依「民國年份」開一個資料夾放進 `data_raw/a2/`，把該年度所有分割檔（不用先合併、檔名不拘）都丟進去即可，例如新增民國 115 年：

```
data_raw/a2/115/115年度A2交通事故資料_1.csv
data_raw/a2/115/115年度A2交通事故資料_2.csv
...（該年度所有分割檔）
```

腳本會自動讀取該資料夾底下所有 `*.csv`、合併去重（依「當事者順位＝1」取事故層級列），計算彙整統計表，並輸出一份 gzip 壓縮後的完整合併原始 CSV 到 `full_data_export/`（給使用者在網站上下載用）。**不需要**手動合併檔案，也不需要在網站程式碼裡新增年度。

> A2 逐年原始檔可能達 2–3 GB，處理時間較長（實測 5 個年度、約 434 萬列，約需 2–3 分鐘），執行時請耐心等待終端機印出進度訊息。

### 3) 更新舉發統計

到 `data_raw/enforcement/` 底下，用新版 xlsx 直接覆蓋對應類別的檔案即可（檔名不用改，例如 `闖紅燈.xlsx`）。只要新版檔案裡有新增的年度列，腳本就會自動讀到。

### 4) 更新縣市統計指標（人口、事故死亡率等長期指標）

直接用新版本覆蓋 `data_raw/indicators/縣市統計指標.xlsx`。

### 5) 更新熱點路口清單（1000易肇事路口 / 799人行安全補助點位）

直接用新版本覆蓋 `data_raw/points/` 底下對應檔名的 xlsx（檔名需完全一致，欄位需包含縣市、鄉鎮市區、緯度 Latitude、經度 Longitude 等既有欄位名稱）。重新執行建置腳本時，會自動：

- 重新輸出點位清單（`points_hotspot1000.data.js` / `points_safety799.data.js`）
- 重新計算每個點位在各半徑內的 A1／A2 環域統計（`point_buffer_a1.data.js` / `point_buffer_a2.data.js`）
- 重新計算縣市／鄉鎮跳轉用的中心座標（`geo_jump.data.js`）

若要新增第三份類似的路口清單，需要請 Claude（或熟悉 Python 的人）在 `build_data.py` 裡仿照 `load_hotspot1000()` / `load_safety799()` 新增一個載入函式，並把新點位一併併入 `all_points`。

> 若清單中的座標尚未地理編碼（緯度/經度欄位空白），環域分析會直接忽略該筆（不計入統計），請先完成地理編碼再放入 `data_raw/points/`。

### 6) 更新各縣市道路交通違規罰鍰收入

到 `data_raw/enforcement_fines/` 底下，用新版本覆蓋現有的 xlsx 檔案（檔名不拘，腳本會自動抓該資料夾下第一個 xlsx）。檔案需包含工作表「道路交通違規罰鍰收入各縣市分配金額」，且維持「分配單位名稱／111年／112年／…／合計／排名」的標題列格式（新增年度欄位、或新增後續年度資料列皆可自動被讀到；若整份改版導致工作表名稱或欄位結構不同，需請 Claude 或熟悉 Python 的人調整 `build_data.py` 裡的 `load_enforcement_fines()`）。

### 7) 更新科技執法設備地點

到 `data_raw/tech_enforcement/` 底下用新版 CSV 覆蓋對應縣市的檔案（檔名需與現有檔案一致，因為 `tech_enforcement.py` 是針對每個縣市檔案的實際欄位名稱個別解析，不是通用格式）。若是新增一個原本沒有資料的縣市（例如新竹縣、宜蘭縣、臺東縣、連江縣），需要請 Claude（或熟悉 Python 的人）在 `scripts/tech_enforcement.py` 裡仿照現有縣市的區塊新增一段解析邏輯，並從 `MISSING_COUNTIES` 清單中移除該縣市。花蓮縣若取得可解析的正式資料（而非僅有 PDF），可直接新增 CSV 並仿照其他縣市寫解析邏輯，取代現行的 PDF 文字解析。

### 8) 更新六都及全國交通標案分類彙整

到 `data_raw/tenders/` 底下用新版 xlsx 覆蓋現有檔案（檔名不拘，取資料夾下第一個 xlsx），需維持原有的工作表名稱與欄位結構（見上方目錄結構說明）。更新後單獨執行：

```bash
cd scripts
python3 build_tenders.py
```

這支腳本獨立於 `build_data.py`，只處理標案資料，不會影響其他資料檔，執行較快。

### 9) 重新產生網站資料

```bash
cd scripts
pip install -r requirements.txt --break-system-packages   # 第一次執行才需要
python3 build_data.py      # 產生 A1/A2/舉發/指標/罰鍰/熱點路口/科技執法 等主要資料
python3 build_tenders.py   # 產生交通標案彙整資料（若 data_raw/tenders/ 有更新才需要）
```

執行完成後，`data/*.data.js` 會自動重新產生，重新整理網頁（或重新部署到 GitHub Pages）就會看到新資料，年度篩選清單也會自動包含新年度，不需要改程式碼。

若原始檔的欄位名稱或格式有變動（例如政府資料平台改版），`build_data.py` 內有詳細註解說明每個資料來源的解析邏輯，可以直接請 Claude（或熟悉 Python 的人）協助調整。

## 資料處理備註

- 事故明細原始 CSV 是「一列一位當事者」，A1、A2 皆然。本站已依「當事者順位＝1」的列取出「一列一件事故」的事故層級欄位（天候、地點、死傷人數等）。A1 當事者層級的欄位（車種、性別、年齡等）保留在 `parties.data.js` 中，用 `aid` 對應回事故的 `id`；A2 因資料量過大，未逐筆保留當事者明細（可從下載的原始 CSV 自行分析）。
- 事故發生地點的縣市是用地址字串比對「發生地點」欄位開頭的縣市名稱取得（因原始資料的「處理單位」欄位對於國道公路警察局、港務警察、鐵路警察等單位無法直接對應到單一縣市），A1、A2 採用相同邏輯。
- 舉發統計與縣市統計指標的歷史縣市名稱（如臺北縣、桃園縣、高雄縣市改制前）已正規化合併到現行 22 縣市。
- **A2 為何用彙整統計、不逐筆載入瀏覽器**：A2 原始資料約 434 萬列、192.6 萬件事故，若比照 A1 逐筆內嵌會產生數百 MB 的 JS 檔，導致網頁載入緩慢、GitHub 儲存庫過於龐大。因此 A2 只在建置時（`build_data.py`）一次性彙整成幾張精簡的統計表（依年度、縣市、月份、小時、事故類型子類別、肇因子類別、10 維交叉表、地圖網格熱區），網站的圖表、地圖、交叉比對皆讀取彙整表；若需逐筆分析，可在「資料表與匯出」分頁下載各年度完整原始資料（gzip 壓縮 CSV，解壓縮後即為政府開放平台格式的原始欄位）。
- 地圖的 A2 熱區是把經緯度四捨五入到小數第 2 位（約 1 公里網格）後加總事故件數，屬於區域密度示意，並非逐點精確位置；A1 則仍保留逐點座標，可切換為叢集標記或熱力圖。
- A1、A2 皆可用側邊欄的年度／縣市篩選；A2 的彙整交叉表（`a2_crosstab.data.js`）額外保留了天候、光線、道路類別、事故類型（大類別）、肇因（大類別）等維度，因此側邊欄的這些篩選條件也會同步套用到 A2 的多維探索與 KPI／趨勢圖上。A2 沒有「死亡人數」欄位（依定義 A2 為僅受傷、無人死亡之事故），量測選項僅提供事故件數／受傷人數。
- 「事故 vs 舉發執法」分頁比對時，僅取事故資料（110–114）與舉發資料（108–114）的重疊年度。
- **各縣市道路交通違規罰鍰收入分配金額**：來源為政府資料開放平台 dataset 167869，目前僅公布 111–114 年（西元 2022–2025）資料，且是「罰鍰收入依規定比例分配給各縣市政府的金額」，跟「舉發件數」是兩份不同的統計（同一舉發案件的罰鍰金額會因車種、違規態樣、有無減免而不同），兩者不會有固定的換算比例，圖表上刻意分開呈現、不強行合併分析。此外原始檔案裡還有「國道公路建設管理基金」「解繳國庫」「罰鍰總收入」等全國性彙總數字，但只有 111 年齊全（其餘年度該資料集尚未公布對應項目），故僅在選到 111 年時於圖表下方額外顯示這幾個補充數字，不納入縣市排行圖表本身。
- 「事故 vs 人口/縣市」分頁的長期趨勢圖使用官方統計指標原始年度範圍（1998–2025），不受年度篩選限制。圖表左軸標題顯示為「每十萬人死亡人數(人)」而非「死亡率」，避免讓人誤會成百分比或死亡機率；圖表下方另外加了一段「名詞定義」說明：這個數字是官方「事故傷害死亡率」指標（ICD-10 死因代碼 V01–X59、Y85–Y86，事故傷害死亡人數 ÷ 年中人口數 × 100,000），涵蓋範圍比「交通事故」更廣（含跌倒、溺水、火災、中毒等所有非蓄意意外死亡），與本站自行統計的 A1/A2 交通事故資料是分開的兩份資料，僅供對照參考。
- **熱點環域分析怎麼算的**：建置時（`build_data.py`）用「空間網格索引」（把點位依經緯度分桶，每筆事故只需跟鄰近幾個網格內的點位比對距離，而不是跟全部 1,797 個點位逐一比對）預先算好每個點位在 50/100/200/300/500/1000 公尺半徑內，A1（用逐筆座標，完全精確）與 A2（同一次掃描 434 萬列原始資料時一併累計，同樣是精確逐筆比對，並非地圖上那種網格估算）的事故件數與死傷人數，結果存成 `point_buffer_a1.data.js` / `point_buffer_a2.data.js`，網站端只要查表即可即時顯示、排序、匯出，不需要在瀏覽器裡重新計算大量距離。
- 地圖上「1000易肇事路口」「799人行安全補助點位」圖層點擊彈窗顯示的是**固定 200 公尺**半徑的統計（供快速預覽），若要看其他半徑（50–1000 公尺）的完整清單與統計，請至「熱點環域分析」分頁。
- 地圖的「座標定位」功能（輸入任意經緯度）可即時計算該座標半徑內的事故概況：A1 用逐筆座標精確計算（可任意調整半徑），A2 因網站僅有約 1 公里網格的彙整資料，是用「涵蓋查詢半徑再加上一個網格寬容度」的網格加總來**概略估算**，半徑愈小時誤差可能愈明顯，僅供概略參考；若需精確的 A2 環域數字，請改用「熱點環域分析」分頁查詢 1000易肇事路口／799人行安全補助點位清單中的既有點位（該清單為精確計算），或自行下載 A2 逐筆原始資料另行分析。
- 地圖「跳到縣市／鄉鎮」的鄉鎮清單與座標，是取「1000易肇事路口」＋「799人行安全補助點位」兩份清單中實際出現過的縣市／鄉鎮並取其點位平均座標而來（涵蓋 144 個有熱點資料的鄉鎮市區，並非全臺 368 鄉鎮市區的完整清單；金門縣、連江縣因兩份清單皆未涵蓋，改用概略縣治座標）。
- 地圖「熱點查詢」（選擇 1000易肇事路口／799人行安全補助點位＋縣市／鄉鎮市區／關鍵字篩選＋選填單一點位＋輸入半徑＋按「查詢」）的「單一點位」欄位為選填：
  - **有選一個點位**時，與「熱點環域分析」分頁在**半徑剛好等於 50/100/200/300/500/1000 公尺**時用的是同一份精確預先計算結果（`point_buffer_a1.data.js` / `point_buffer_a2.data.js`），此時 A1、A2 皆為精確值；輸入其他任意半徑時 A1 仍即時逐筆精確計算，但 A2 改用與「座標定位」相同的網格概略估算法（約 1.1 公里網格＋容許寬容度），半徑越小估算誤差可能越明顯。
  - **保持預設「不指定單一點位」**時，會直接對目前縣市／鄉鎮／關鍵字篩選出的「所有」點位一次查詢：採用「去重」合計（同一筆 A1 事故或同一個 A2 網格，只要落在任一篩選點位的半徑內就只算一次），避免點位彼此靠近時被每個點位的環域各自重複計算、導致總數膨脹失真；此模式下 A1 仍為精確逐筆計算，A2 一律為網格概略估算（不論半徑是否為固定選項）。地圖上一次最多畫出前 300 個點位的範圍圈（統計數字仍涵蓋全部符合條件的點位）。
  - 查詢結果文字與「⬇ 匯出符合條件點位」CSV（新增「A2統計方式」/「A2是否精確」欄位）都會清楚標示 A2 統計是「精確」還是「概略估算」。匯出永遠是依目前篩選匯出「所有」符合條件的點位各自的統計（不是去重合計），與是否有選取單一點位無關；如果想要的是所有篩選點位「加總不重複」的總數，請直接看查詢結果文字裡的合計。
  - 「熱點環域分析」分頁則是另外的完整清單頁面，可排序、依縣市或關鍵字篩選並整批匯出（僅支援上述固定半徑選項）。
- **改善趨勢分析分頁的兩種百分比定義**（刻意分開兩種算法，避免像先前「死亡率」被誤解為機率一樣的混淆）：
  - **改善%**：只用在事故／死傷相關的 5 項安全指標，定義為 `(起始年數值－結束年數值) ÷ 起始年數值 × 100%`。**正值（綠色）＝數值減少＝改善；負值（紅色）＝數值增加＝惡化**。
  - **變化%**：只用在「舉發總件數」「罰鍰收入」這類中性指標（不預設好壞），定義為 `(結束年數值－起始年數值) ÷ 起始年數值 × 100%`。正值＝增加，負值＝減少，純描述方向。
  - 5 項安全指標各自可用的年度範圍不同：A1 死亡人數／A1 事故件數為 A1 資料涵蓋年度（110–114 年）；A2 事故件數／A2 受傷人數為 A2 資料涵蓋年度（110–114 年）；「每十萬人死亡率」為官方統計指標涵蓋年度（1998–2025 年，範圍最完整）。全國整體改善總覽卡片會各自使用該指標**現有的完整年度範圍**（卡片標題會標示實際用的起始→結束年），並非統一年度。
  - 各縣市改善排行：若某縣市在所選指標／年度沒有資料（最常見情形是「每十萬人死亡率」因該年死亡人數未滿 20 人、自 112 年起官方以「*」標示為不可靠而未公布），該縣市會直接從排行中排除，不會用 0 或估計值頂替，畫面下方會註明排除的縣市數。
  - 舉發／罰鍰對照象限圖：X 軸年度範圍取「所選安全指標的可用年度」與「舉發資料（108–114）／罰鍰資料（111–114）的可用年度」兩者的**交集**，切換不同安全指標時，年度選單會自動重新計算交集並可能跟著改變。兩軸的分界線是**目前顯示縣市在該軸的平均值**（並非 0），會隨著縣市篩選、指標、起訖年變動即時重新計算；用平均值分界的用意是凸顯「哪些縣市明顯偏離整體平均」，而不是用「有沒有增加/減少」這種絕對零點來分。四個象限分別用四種顏色標示（右上／左上／左下／右下），圖表下方會列出各象限實際包含哪些縣市，方便一次看出縣市間的差異分群；兩張圖也都可以「匯出 CSV」，內容為目前畫面上每個縣市的 X／Y 軸數值、所在象限、以及當下的分界平均值。這兩張圖僅呈現描述性關聯，**不代表因果關係**：事故改善或惡化通常是執法強度、道路工程、車流量、人口結構、經濟活動等多重因素共同影響的結果，圖表下方的說明文字也重複強調此點，避免使用者誤讀成「罰得越多／舉發越多＝越安全」之類的因果結論。
  - 此分頁的縣市排行、散佈圖皆會即時套用側邊欄的縣市篩選；但「全國整體改善總覽」卡片固定顯示全國 22 縣市加總／官方全國指標，不受縣市篩選影響（用意是提供一個不會因篩選而變動的全國基準參考）。
- **縣市道路安全結構關聯分析**（改善趨勢分析分頁下半段，比對「縣市結構性因素」與「安全結果」的橫斷面關聯）：
  - 跟上面的改善趨勢卡片不同，這裡比的是同一年度、不同縣市之間的差異（橫斷面），不是同一縣市逐年的變化，所以只選單一年度（而非起訖年）。
  - X 軸「縣市結構因素」全部來自官方「縣市統計指標」既有欄位換算：每萬人道路里程（道路里程長度 ÷ 人口 × 10,000）、人口密度（官方指標直接使用）、65歲以上／0-14歲人口比例（該齡層人口 ÷ 總人口）、每萬人小客車登記數。Y 軸「安全結果」為了讓人口規模差異很大的縣市（例如連江縣 vs 新北市）可以公平比較，一律換算成「每十萬人／每萬人」標準化比率，或本身即為比例的指標：每十萬人死亡率（官方指標）、A1死亡人數／A2受傷人數（皆除以當年人口再換算成每十萬人）、道路交通事故肇事總件數（官方統計，換算成每萬人）、A1或A2事故中「人與汽(機)車」「人與車」類型（行人涉入）所占比例。
  - 象限分界線同樣是「目前顯示縣市在 X、Y 軸的平均值」，並非 0；四象限著色、下方縣市清單、CSV 匯出的呈現方式跟上面的改善趨勢象限圖一致。
  - **這裡呈現的是關聯（correlation），不是因果關係**：道路長度、人口密度、高齡化程度等縣市結構因素彼此高度相關，也都同時受到都市發展程度、地理條件等因素影響，不宜直接推論「蓋更多路會更危險」「人口越老越危險」之類的單一因果結論，圖表下方的說明文字也重複提醒這點。
  - **當事者年齡結構 vs 人口年齡結構（涉入比）**：涉入比定義為「該縣市當事者中某齡層所占比例 ÷ 該縣市人口中同齡層所占比例（採用結束年人口資料）」，涉入比＝1 代表該齡層在當事者中的占比恰好等於其人口占比，大於 1 代表相對超額、小於 1 代表相對偏低。
    - **重要資料限制**：政府公開的 A1/A2 逐筆資料只記錄「每一位當事者」（含駕駛人、乘客、行人等所有涉入該事故者）的年齡，**並未標示該事故中誰是死者、誰是傷者、誰是肇事責任方**。因此本站以「A1（死亡事故）當事者年齡」作為死亡事故相關年齡結構的替代／近似指標，**並非「死者年齡」本身**；同理 A2 涉入比反映的是「受傷事故當事者」的年齡結構，不代表「受傷者年齡」或「肇事者年齡」。這點跟前面「每十萬人死亡率」的資料來源與定義都不同，請勿混用。
    - A1 的當事者年齡分布是用 `parties.data.js`（逐筆保留、依 `aid` 對應回 `accidents.data.js` 取得縣市／年度）即時在瀏覽器端計算；A2 因資料量過大，年齡分層是在建置時（`build_data.py`）與其他 A2 彙整同一次掃描一併累計成 `a2_age_bracket.data.js`（逐筆列都計入，不像其他 A2 彙整只取當事者順位=1 的事故層級列，因為年齡是「當事者」層級的屬性）。年齡欄位為空白或代碼 -1（無法查明）的當事者不計入任何分母/分子。
    - 涉入比偏高不必然代表該齡層「肇事責任」較高，也可能反映該齡層本身的用路方式或暴露量（例如高齡者步行機會較多、較常以行人身分涉入事故）。65 歲以上或 0-14 歲若涉入比明顯偏高，通常較值得從行人安全、通學通勤動線等面向優先檢視；15-64 歲（工作年齡）由於本身也是主要駕駛人口，涉入比略高於 1 是常態，不宜比照高齡／幼年層的解讀方式。

- **科技執法設備地點資料的已知缺口與限制（請務必留意，不要直接引用為「全國科技執法設備完整清單」）**：
  - 22 縣市中，**新竹縣、宜蘭縣、臺東縣、連江縣完全沒有提供資料**（原始資料包中無這4個縣市的檔案）。

  - 苗栗縣「區間測速設備取締件數」、國道5號雪山隧道科技執法系統，原始資料同樣只有路段描述沒有座標，處理方式同上。
  - 全部 1,243 筆中僅 880 筆（約71%）有可用經緯度，網站地圖圖層與「熱點環域分析」僅涵蓋這 880 筆；其餘 363 筆（含花蓮全部、以上里程描述型設備、少數座標欄位本身就有錯誤資料的列）僅保留於資料檔中供表格查詢，不納入地圖與環域統計。
